# Bash 与本地 pi TUI 的兼容要求

状态：V1 必须实现的产品约束。Bash 是[整体 TUI 体验原则](tui-experience.md)的一个具体对照项，原生能力优先适用于工具、资源、会话、控制和交互全部方面。本约束适用于 [架构](v1-design.md)、[协议](protocol-v1.md)、[进程恢复](deployment.md)及[开发计划](development-plan.md)；早期限制普通 Bash 或后台服务的表述已撤回。

## 1. 兼容基线

使用固定 `@earendil-works/pi-coding-agent@0.85.1` 的原生 Bash 工具及默认本地执行实现。对比条件为同一 Linux 工具链、UID/GID、cwd、环境变量、shellPath、pi 配置与可信扩展；本地 pi TUI 在该环境可以运行的 Bash，后端不能因手机接入额外禁用、改写或要求批准。

应用负责会话、通信、持久化和手机显示。普通 Bash 命令不使用白名单 / 黑名单，不转成受限命令 DSL，不为每条命令增加确认，不根据命令名称或语法自动拒绝。保留管道、重定向、复合命令、脚本、网络访问、依赖安装、Git、构建测试以及后台服务等原生能力。项目注册的路径校验只决定 cwd 与归属，不成为 Bash 的文件访问沙箱。

同样保留 SDK 的命令 schema、工具描述、返回给模型的结果、错误及输出截断语义。手机事件从 SDK 输出旁路转换；不得用手机显示长度、artifact 配额或慢连接反向裁剪模型看到的工具结果、改写命令或结束 Bash。运营者配置的 shell / 环境 / 扩展按同一基线加载，应用不额外注入命令过滤 hook。

容器应作为完整 Linux 开发环境配置：提供项目所需的工具链、PATH、可写 HOME / cache、网络、Git / 包源凭据及挂载。权限错误按真实 OS / 部署配置报告；不能把缺少的开发环境能力包装成 Bash 产品限制。Docker 服务连接、额外挂载与系统权限由运营者按项目配置，不是每次 Bash 执行的应用审批流程。

## 2. 时限、任务与后台服务

- Bash 未传 timeout 时没有应用默认时限。SDK 显式 timeout 按原生语义传入；HTTP 超时、WSS 心跳、手机锁屏、无输出时间和 worker 空闲回收计时都不能变成命令超时。默认禁用空闲回收；运营者开启时，只能回收没有活动调用 / 待答操作的 worker。
- 前台长任务持续显示运行，按 SDK 提供的输出更新。工具返回错误时交给 pi 继续推理、修复及重试，不能把一次测试失败直接变成整个 Run 失败或暂停队列。
- `&`、nohup、setsid、开发服务器和 watch 进程可按原生 shell 用法启动。命令是否返回由 SDK 判断；未正确重定向的后台进程可能继续占用输出流，也沿用原生行为，应用不通过猜测语法改成另一种运行方式。
- 当 SDK 已返回该命令的最终结果，留下的正常后台服务不再占用活动工具槽；agent settle 后 Run 可完成，下一次 prompt 可访问服务。不能因为还有后台 PID、端口或文件写入就把项目标为 blocked，或等待所有后代进程退出才结束 Run。
- 正常结束、切换页面 / Session、断网、归档及空闲 worker 回收不额外扫杀已启动的后台服务。它们继续属于当前 Linux / app 容器的运行环境；在后续 Bash 中查看日志、检查端口或停止进程。V1 无需另建后台服务管理器，也不承诺恢复尚未重定向并已关闭的 stdout。
- 模型 `/stop` 按 TUI 先 clearQueue 并保存未消费输入为草稿，再调用 SDK abort，作用于当前 Run 的未完成调用。用户直接 `!` / `!!` 使用独立 Bash Operation，停止入口调用 Session 级 abortBash，范围是当前用户 Bash 调用集合。两者都不扩大到已正常返回的后台服务，详见[原生运行契约](native-runtime-contract.md)。显式停止整个 app 容器会终止其中服务。

不同 Session 默认允许在同一工作区并行；同 Session 输入遵循原生 steer / follow-up。运营者按实际需要开启 workspaceKey 串行时也只串行 agent Run，不承诺“整个目录最多一个 OS writer”。正常后台服务可与后续 Run 并存，其文件 / Git 协调与本地开发相同。

## 3. 故障恢复边界

已收到最终工具结果的后台服务与尚未收到结果就崩溃的 Bash 调用必须区分。在**活动 Run 的调用分派后、最终状态确认前**出现 worker / 主进程崩溃或停止失败时，保留 interrupted / unknown，只暂停已有后续项，不自动重投未知命令。用户仍可明确发起新操作；空队列不需恢复，空闲 worker 退出或发现后台 PID 不成为项目封锁理由。

普通 docker compose up 即可启动；不要求宿主 helper、清理证明或整容器恢复才能继续。若实际遇到残留进程、端口冲突等问题，准确报告并按[部署约定](deployment.md)诊断和定向处理；必要时由运营者重启容器。重启会影响该环境内其他任务与服务，不能作为每个 Run 的收尾步骤。

对应用已持久化的最终工具结果，恢复代码不能因为 SDK 管理进程稍后退出又将工具成功改成 unknown；Run 是否完整结束另按其持久状态判断。若最终结果只停留在内存、尚未提交就崩溃，则属于真实未知窗口，不能捏造成功或自动重跑。

## 4. 必须执行的对照验证

下表对应 FR13 / AT31，阶段归属见[验收矩阵](acceptance.md)。S02 先用同版本原生 SDK 执行器作确定性基线，再在同一 Linux 环境打开 pi TUI 做真实 smoke；S06、S10、S12 逐步用相同任务验证服务生命周期、手机与部署。比较命令、文件、退出 / 错误语义及输出标记；PID、时间戳和流式分块可以不同，不要求模型生成完全相同的措辞。

| 对照项 | 操作 | 通过条件 |
| --- | --- | --- |
| B01 命令与环境 | 管道、重定向、条件 / 复合命令、脚本；读取 cwd 外当前 OS 用户可读的测试文件；核对 PATH / HOME / shell 配置 | 与原生 SDK / TUI 相同；无额外命令过滤、确认或路径沙箱 |
| B02 开发工具与网络 | 临时 Git 项目、通过测试包源安装依赖、构建 / 测试；curl 访问测试 HTTP 服务 | 实际执行并验证文件 / 网络结果；不因是 Git、网络或安装操作而拒绝 |
| B03 长运行与 timeout | 未传 timeout 的任务运行超过 300 秒，期间可无输出、手机断开；另测显式短 timeout 和运营者开启回收的配置 | 前者持续执行且不被空闲回收，后者按原生超时终止；默认回收为 0，测试 harness 自己的总时限不得成为生产默认 |
| B04 后台服务 | 原生 Bash 启动重定向输出的 nohup / 后台测试服务，返回后继续 prompt、断网、切换 Session、归档；另在明确开启回收的配置下测试 | 服务仍响应且日志继续增长，无额外清理、无 busy / blocked；后续 Bash 可以检查和停止它 |
| B05 定向停止 | 先启动已正常返回的后台服务，再执行另一条前台长命令并 `/stop` | 当前调用按 SDK 中止；原服务不被应用扩大清理范围而结束；不要求服务全部退出才认定 stopped |
| B06 非零工具退出 | 一次测试命令非零退出，pi 读取错误并修复，再运行通过 | 工具错误原样可见且供模型使用；Run 不因第一条工具错误被应用提前终止 |
| B07 输出与显示 | 混合 stdout / stderr、超过 SDK 原生显示长度及手机 artifact 配额的大输出 | 模型结果与原生相同；手机累计输出不重复、有明确分页 / 截断说明；SDK 保留的输出文件仍可由后续 Bash 读取，手机配额不杀命令 |
| B08 未完成调用崩溃 | 前台 Bash 尚未返回时 SIGKILL worker；与 B04 已返回服务及可选回收分别比较 | 未知结果如实保留，旧命令不自动重投、已有后续项暂停；用户新明确操作可继续，无强制项目冻结或清理证明；正常后台服务不被误判为故障，实际 Docker 故障处理按 AT25 验证 |

所有样例使用临时项目与受控测试服务，测试结束清理其进程和数据；这些测试夹具不代表生产命令范围受限。缺少真实模型、TUI、Docker 或手机证据时记录 not_run，不能把文档检查通过写成 Bash 兼容已验证。

## 5. 已核对的源码

- [Bash 工具](https://github.com/earendil-works/pi/blob/d981de1229ef899957bbe968bc8dcda02a21f477/packages/coding-agent/src/core/tools/bash.ts)：timeout 可选且无默认值；采用 detached shell；调用结束后取消该 shell PID 的活动跟踪；原生输出累积和结果构造。
- [子进程等待](https://github.com/earendil-works/pi/blob/d981de1229ef899957bbe968bc8dcda02a21f477/packages/coding-agent/src/utils/child-process.ts)：处理 shell 已退出但后代仍持有 stdout / stderr 的情况，持续输出会延后完成，安静继承句柄不会无限挂起。
- [Shell 环境与清理](https://github.com/earendil-works/pi/blob/d981de1229ef899957bbe968bc8dcda02a21f477/packages/coding-agent/src/utils/shell.ts)：shell 配置、环境继承、活动 detached child 跟踪与进程组停止。stdin / TTY 和交互方式也以同版本原生工具为基线，不额外承诺 SDK 本身没有的终端能力。
